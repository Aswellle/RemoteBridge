# RemoteBridge v2.2.0 发行版

> 发布日期：2026-09-25  
> 桌面端：v2.2.0 | 服务端：v1.1.0 | Web：v1.0.1

---

## 概览

本次发行聚焦**信息可见性**与**连接状态面板的重构**。桌面端「连接状态」面板从原先平铺的 6 个同类格子，改为按重要度分组的 2 列信息架构（桌面宽度）/ 单列（窄窗口），并补齐了**桌面端 / 服务器 / Web 端三个真实版本的展示**——其中 Web 端版本通过新增的客户端自报链路实时获取，不再显示 Electron / Node 等框架运行时版本（运行时信息仍保留在「关于」页）。

**更新规模**：自 v2.1.0 起 2 个功能提交，跨 desktop / server / web / shared 四个包，新增 1 个 UI 原语、1 个服务端测试、1 个 IPC handler。

---

## 重点内容：你现在可以

- **一眼看清三个版本**：连接状态面板直接显示「桌面端 vX / 服务器 vY / Web 端 vZ」，服务器版本来自中继 `/health` 实时查询，Web 端版本来自客户端握手自报。
- **连接状态信息分层更清晰**：按「连接 → 客户端 → 版本 → 本机」分组，组间距 24px / 组内 8px；桌面宽度下 2 列排布，窄窗口（≤md）自动回落单列且无横向溢出。
- **服务器与 Web 端版本真实可溯源**：不再写死占位值；中继不可达或暂无 Web 端连接时以 `—` + 说明降级展示。
- **更新检查失败不再遮挡操作**：检查 / 下载失败不再进入全局横幅，错误仅在「关于」页内联提示；横幅只承载「可升级」这类需要你操作的状态，并支持按版本号记忆关闭。
- **客户端版本安全上报**：Web 端上报的版本经严格字符集校验，非法值不会进入 Host 端界面。

## 新功能

### 客户端版本上报链路（Web → Relay → Host）

`apps/web/src/lib/env.ts`、`apps/web/src/hooks/useWebSocket.ts`、`apps/server/src/ws/handler.ts`、`apps/server/src/ws/connection-registry.ts`、`apps/server/src/routes/hosts.ts`、`packages/shared/src/api-types.ts`

- Web 端构建时从 `package.json` 注入版本号（`next.config.mjs` → `NEXT_PUBLIC_APP_VERSION`），WS 握手 URL 追加 `&ver=`
- Relay 解析并严格校验 `ver`（`^[0-9A-Za-z][0-9A-Za-z.+-]{0,31}$`）：该值会进入 Host 端界面，非法值一律视为未上报
- 版本记录在 Relay 内存注册表（客户端断开即失效，**不落库、无需迁移**）；同一设备重连未上报时清除残留值
- `GET /hosts/:hostId/clients` 对在线客户端返回 `version` 字段，Host 端据此展示

### 中继服务端版本实时查询

`apps/desktop/src/main/ipc/settings.ts`、`apps/desktop/src/preload/index.ts`

- 新增 `relay:get-server-info` IPC：读中继 `/health`（公开端点，无需 token），返回 `version` / `instanceId`
- 主进程内 60s 缓存，避免每次渲染都打一次网络；`/health` 位于源站根路径，自动从 `relayApiUrl` 回退到 origin

### 连接状态面板 2 列分组信息架构

`apps/desktop/src/renderer/App.tsx`

- 原先 6 个同类样式格子平铺，改为按重要度分四组：**连接 → 客户端 → 版本 → 本机**
- 分组间距 24px / 组内 8px（≥2× 对比，空间优先于分割线承载分组）
- 桌面宽度下 **2 列排布**：单列占满宽度时标签与值的水平距离逾 700px（视线往返成本高），2 列收敛到列宽内；窄窗口（≤md）自动回落单列
- 版本区块显示桌面端 / 服务器 / Web 端三个版本，**不再显示 Electron / Node 等框架与运行时版本**（运行时信息仍保留在「关于」页）；不可达或暂无连接时以 `—` + 说明降级展示

### 信息展示字重与样式规范化

`apps/desktop/src/renderer/App.tsx`

- 组标题：12px 半粗 + 大写 + 字距（`uppercase tracking-wider`）
- 标签：12px 次级色（`text-muted-foreground`）
- 值：14px 中等字重（`font-medium`），主机名与版本号用等宽字体（13px `font-mono`）
- 补充说明：12px / 1.4 行高（多行文本至少 1.4，避免行拥挤）
- 延迟与会话数：`tabular-nums` 防止刷新时数字宽度变化引起跳动
- 状态指示：统一改用 `StatusDot` 原语（原先手写圆点 + 内联三元颜色判断）
- 连接 / 重试 / 断开按钮：改为可见描边样式，符合「每屏仅一处主操作」层级

### 新增 DataList / DataRow UI 原语

`apps/desktop/src/renderer/components/ui/DataList.tsx`

- 只读「标签 + 值」信息列表，使用 `<dl>/<dt>/<dd>` 语义结构（标签与值配对可被辅助技术读出）
- 支持等宽字体（`mono`，主机名 / 路径 / 版本号）、表格数字（`numeric`，延迟 / 计数）、长值 `truncate` + `title` 兜底
- 行间距 8px（`space-y-2`），与 ≥16px 的区块间距形成分组对比

### 侧栏底部系统信息视觉升级

`apps/desktop/src/renderer/App.tsx`

- 改为浅面板承载（以背景形状 `bg-surface-raised/60` 与导航区分离，而非再加一条分割线）
- 标签左、值右对齐，主机名与系统各占一行；长主机名截断并保留 `title` 完整值

### 更新检查失败不再占用全局横幅

`apps/desktop/src/main/updater.ts`、`apps/desktop/src/renderer/App.tsx`

- 检查 / 下载失败**不再进入全局状态**：错误经 IPC 返回值交给调用方，仅在「关于」页内联提示
- `UpdateStatus` 类型移除 `error` 变体（类型层面杜绝「错误横幅」）
- 顶部横幅只承载「需要用户动作」的三态：发现新版本 / 下载中 / 已就绪；均带最右侧 ✕
- 关闭状态按版本号记忆（同一版本不再弹出，出现更新的版本时重新提示）
- 下载中途失败时把状态退回「可下载」（记录 `lastAvailableVersion`），避免横幅永久停在进度条上

## 修复

### 本地中继启动端口探测在 Node 20 下崩溃

`apps/desktop/src/main/local-relay.ts`、`apps/desktop/tsconfig.json`

- `probePort` 使用了 `Promise.withResolvers`，该 API 需要 Node ≥22（V8 ≥12.4）；仓库 `engines` 声明 `>=20` 且 CI 使用 `node-version: 20`，实际运行时报 `Promise.withResolvers is not a function`，`local-relay-probe` 4 个用例全部失败
- 更严重的是探测抛错时 `starting` 标志不会复位，后续所有启动请求都会被「本地 Relay 正在启动中」永久挡掉（CI 输出中另外 3 个用例由此连带产生）
- 改用通用 `new Promise` 写法，并把 `starting` 复位移入 `.finally`，保证异常路径也能释放
- 回退 `tsconfig` 中为 `withResolvers` 引入的 `ES2024.Promise` lib：基础 lib 回到 ES2020 后，此类 API 会被类型检查直接拦下

### 更新横幅长期驻留遮挡正常操作

`apps/desktop/src/main/updater.ts`、`apps/desktop/src/renderer/App.tsx`

- 一次网络抖动（`net::ERR_CONNECTION_CLOSED`）会被广播成全局 `error` 状态，顶部横幅此后一直显示「检查更新失败」并遮挡正常操作；且没有任何清除 / 关闭手段。现已改为错误不进入全局状态

### 下载失败卡在进度条无法再操作

`apps/desktop/src/main/updater.ts`

- 下载中途失败原先会让横幅永久停在进度条上。现已退回「可下载」状态（记录 `lastAvailableVersion`），恢复可操作

## 升级提醒

### 兼容性

- **数据库**：无 schema 变更，无迁移（客户端版本仅存在于 Relay 内存注册表）
- **协议**：与 v2.1.0 完全兼容；WS 握手新增可选 `&ver=` 参数，旧版客户端不受影响
- **旧版 Web 客户端**：连接时不再上报版本，Host 端显示 `—`（`暂无 Web 端连接`），无功能影响
- **自动更新**：需 GitHub Releases 存在高于当前版本的 tag 才会触发

### 服务端升级

服务端由 v1.0.0 升至 v1.1.0（新增客户端版本内存注册与返回）。Docker 部署直接拉取新镜像即可，无迁移步骤。
