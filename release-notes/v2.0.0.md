# RemoteBridge v2.0.0 发行版

> 发布日期：2026-09-14
> 桌面端：v2.0.0 | 服务端：v1.0.0 | Web：v1.0.0

---

## 概览

自 v1.3.11 以来，RemoteBridge 经历了一次面向文件传输链路的架构升级。本版的核心是 **V2 Transfer Engine**——一套覆盖 Web 浏览器 ↔ Relay ↔ 桌面 Host 三端的统一传输模型，把过去仅支持「下载」的流式隧道扩展为支持**上传 / 下载 / 预览**三个方向、具备**协议级取消、背压传播、序列与字节完整性校验**的完整传输状态机。围绕这条主链，同步落地了**不透明资源句柄**（文件路径不再出现在 URL 中）、**V2 二进制流式分片上传**、**PathGuard V2 路径守卫**（最长匹配 + 审计日志 + Windows 规范化 + TOCTOU 缓解）、**PIN HMAC 索引查找**（O(1) 连接认证）等安全加固，以及 Web 端 Zustand Store 的拆分重构与大文件预览的分片加载。

**更新规模**：28 commits | 78 files changed | +7,290 / -1,127 lines

---

## 重点内容：你现在可以

- **从 Web 端向桌面端流式上传大文件**：Web 端使用浏览器原生 `File.stream()` 与二进制 WebSocket 帧逐块上传，桌面端写入临时 `.part` 文件后原子重命名为最终路径，支持并发上传配额（5 个）、单文件 100 MB 上限、序列校验与路径穿越防护。
- **取消正在传输的文件**：协议级取消（`CMD_CANCEL_TRANSFER`）可中断任意方向的传输；浏览器关闭时 Relay 主动向 Host 下发取消，Host 通过 `AbortController` 立即终止磁盘读取。
- **在 URL 中不再暴露文件路径**：新增 `ResourceRegistry` 生成带 TTL 的不透明资源 ID，Web 客户端优先使用 `resourceId` 访问文件，彻底消除 URL 中的 `filePath` 泄露风险。
- **大文件预览按需加载**：超过 50 MB 的文件仅通过 `Range` 请求前 1 MB，TextViewer 显示分片预览提示条，避免浏览器因单文件过大而卡顿。
- **桌面端路径守卫升级至 V2**：最长路径匹配支持嵌套允许目录、所有拒登尝试写入审计日志、Windows 路径大小写不敏感规范化、TOCTOU 竞争缓解辅助函数。
- **Web 端状态管理拆分为 6 个专注 Store**：transfer / session / file / preview / message，职责边界更清晰，附带 14 个新增测试。

## 新功能

### V2 Transfer Engine — 统一传输模型与状态机

新增 `packages/shared/src/transfer/` 模块，定义跨四包共享的 `TransferRecord`、传输方向（`download` / `upload` / `preview`）与 `BaseTransferManager` 状态机。服务端 `apps/server/src/ws/file-tunnel.ts` 包装为单例 `transfer-registry`，Web 端 `apps/web/src/store/transfer-store.ts` 扩展为 `WebTransferManager`，管理 `downloadUrl` / `previewUrl` / `abortController`。

协议层面新增 `CMD_CANCEL_TRANSFER` 与 `RESP_TRANSFER_STATE` 消息类型、`TransferState` 枚举（`PENDING → ACCEPTED → STREAMING → COMPLETED | FAILED | CANCELLED`），以及 `packages/shared/src/protocol/` 运行时消息校验器（`validateMessage()` + 类型化错误层级 `ProtocolError`）。所有 9 种 JSON WS 消息在 Handler 边界统一校验。

关键不变量：
- 每次传输拥有唯一 `transferId` 与显式状态流转
- 取消幂等，沿会话级联撤销（客户端断连时自动取消其全部传输）
- 序列间隙与字节数不匹配触发 `FAILED`
- HTTP `write()` 排空背压自动传播到 Host 磁盘读取
- 每次取消写入 `security_logs`（fire-and-forget）

### V2 二进制流式分片上传

替换旧版 base64 缓冲上传为端到端二进制流：
- **协议**（`5d2f0eb`）：新增 `UPLOAD_START` / `UPLOAD_END` / `UPLOAD_CANCEL` 控制消息与 `encodeUploadChunkFrame()` / `decodeUploadChunkFrame()` 自描述二进制帧（版本、标志、transferId、序号、数据）
- **服务端中继**（`53bad76`）：路由上传控制消息，新增 `relayBinaryToHost()` 转发客户端二进制分片到 Host
- **桌面 Host**（`8b4f61a`）：`onBinary` 客户端处理流写入 `.part` 临时文件，原子重命名为唯一路径；并发上传配额 5，单文件 100 MB，序列校验，路径穿越防护；10 个并发同名的原子提交测试验证 O_EXCL 竞争安全
- **Web 客户端**（`77441dc`）：`File.stream()` + `ReadableStream` 分块读取，浏览器原生 `DataView` 编码二进制帧

### 不透明资源句柄（P1-04）

新增 `ResourceRegistry`，基于 TTL 的不透明资源 ID。Relay 在处理 `CMD_REQUEST_DOWNLOAD/PREVIEW` 时创建 `resourceId` 注入到 `RESP_*_READY` 响应中。新增 `/proxy/resource/:resourceId` 路由，无需在 URL 暴露 `filePath` 即可访问文件。Web 客户端优先使用 `resourceId`，向后兼容回退到旧版 `filePath` 查询参数。

### PathGuard V2 — 桌面端路径守卫升级

`apps/desktop/src/main/security/path-guard.ts`：
- **最长路径匹配**：正确支持嵌套允许目录场景
- **审计日志**：所有拒登尝试通过 `log.warn` 记录
- **Windows 路径规范化**：大小写不敏感、反斜杠标准化
- **TOCTOU 缓解**：新增 `validatePathTOCTOU()` 与 `clearPathCache()` 辅助函数

### PIN HMAC 索引查找（P1-06）

新增部分索引 `idx_hosts_pin_hmac ON hosts(pin_hmac)`，实现精确 HMAC 匹配。`auth.ts` 连接时先计算 PIN HMAC，走索引 SQL 查找（O(1)），再做单次 bcrypt 校验——替代原有的 O(n) 全表扫描 + bcrypt 循环。附带基准测试验证。

### 大文件预览分片加载（P1-08）

新增 `PREVIEW_SIZE_THRESHOLD`（50 MB）与 `PREVIEW_PARTIAL_BYTES`（1 MB）常量。大文件预览使用 `Range` 请求仅获取前 1 MB；`PreviewState` 新增 `isPartial` 标志传递到 `TextViewer`，显示分片预览提示条。

### Web 端 Store 拆分（P1-09）

将单一 `AppStore` 拆分为 6 个专注 Zustand Store：
- `transfer-store`：文件传输与进度追踪
- `session-store`：连接状态、会话、WebSocket 实例
- `file-store`：文件浏览器状态（目录、条目、加载）
- `preview-store`：文件预览状态（URL、字节数、类别、分片标志）
- `message-store`：聊天消息与未读数

新增 `stores.ts` 桶出口，附带 14 个覆盖全部 Store 操作的测试。

### 主机文件服务端加固

`apps/desktop/src/main/file-server/server.ts`：
- 严格 Range 校验：不可满足范围返回 416（不再静默截断）
- 所有响应添加 `ETag` 与 `Last-Modified` 头
- 活动内容（`html/htm/xhtml/svg`）在 `/preview` 强制 `Content-Disktop; attachment`
- 安全头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`
- 预览响应添加 `Content-Security-Policy: sandbox`

### 主机文件隧道加固

`apps/desktop/src/main/ws-client/file-tunnel.ts`：
- 每传输 `AbortController` 注册表，立即取消磁盘读取
- `CMD_CANCEL_TRANSFER` 处理 Relay 取消
- 严格 Range 校验：`start >= fileSize` 时返回 `RESP_FILE_ERROR`

## 变更

### 服务端 / 协议

- **运行时消息校验上线**：`apps/server/src/ws/handler.ts` 在处理边界接入 `validateMessage()`，所有传入 JSON WS 消息经 `packages/shared/src/protocol/schemas.ts` 校验
- **取消协议接入**：`CMD_CANCEL_TRANSFER` 消息类型处理 Relay→Host 与 Host 发起的取消
- **会话撤销级联取消**：`apps/server/src/routes/auth.ts` 撤销处理先调用 `cancelTransfersBySession` 再通知客户端
- **代理隧道排空背压**：`apps/server/src/routes/proxy.ts` 的 `tunnelFromHost()` 使用异步 `onChunk` + `raw.write()` 排空，浏览器关闭时下发取消
- **严格 Range 语义**：新增共享 `parseRangeHeader()` 与 `validateRangeAgainstSize()` 辅助函数（`packages/shared/src/protocol/`），不满足范围返回 416

### 文档与基础设施

- **内部设计/运维文档移出公开仓库**（`129c30e`）：移除 7 个不面向用户的内部文档（代码评审报告、file-tunnel 二进制帧设计、httpOnly cookie 令牌设计、可观测性日志迁移、relay 房间状态设计、运维 runbook）
- **公开仓库新增完整文档**（`04a970c`）：AGENTS.md、使用说明书、生产部署指南、CHANGELOG.md、docs/adr/ 架构决策记录（ADR-004、ADR-005）
- **README 更新**（`64b6a6e`）：Electron 28→29、Next.js 14→15、V2 Transfer Engine 特性、活动内容隔离（HTML/SVG 强制附件）、运行时 WS 消息校验
- **AGENTS.md 更新**（`6381ff5`）：V2 Transfer Engine 架构图、状态机、取消协议、每传输 AbortController、严格 Range 校验、活动内容隔离、运行时消息校验约定

### Web 端

- **活动内容隔离（RB-P0-05）**：Web 预览组件 `FilePreview.tsx` 对活动类型显示"无法预览"并提供下载按钮，PDF / 图片 / 文本预览路径不变

## 修复

### 协议校验器保留额外负载字段（RB-P0-06）

`f7b9fc4`：`packages/shared/src/protocol/schemas.ts` 校验器此前返回仅含已校验字段的新对象，剥离了 Handler 用于消息路由与持久化的 `clientId`、`messageId` 等字段。现在展开原始负载保留全部附加字段，同时仍校验已知字段。修复 Host→Client 消息中继与持久化测试失败。

### MSG_TEXT 校验器使 senderId/senderLabel 可选

`6fac575`：客户端发出的 `MSG_TEXT` 仅含 `{ content }`；中继层在 `handleMessage` 期间追加 `senderId` 与 `senderLabel`。校验器此前拒绝缺少这两个字段的合法消息为 `INVALID_PAYLOAD`，破坏全部消息中继与持久化测试。

### 上传配额再校验与并发竞争安全

- `318a9c1`：10 个并发同名上传的原子提交测试，验证 O_EXCL 竞争安全唯一文件名分配，确认写入失败时原子重命名不残留部分文件
- `db8bf6f`：上传配额——单文件 100 MB 上限 + 分块再校验（D1 修复）

### 活动类型文件强制附件

`0db2eed`：更新 `file-server.test.ts` 反映活动内容隔离：HTML 文件现在以 `application/octet-stream` + `Content-Disposition: attachment` 提供；新增安全头测试（`X-Content-Type-Options`、`Referrer-Policy`）与活动类型强制测试。

### 依赖漏洞修补

`0db2eed`：`fast-uri >=4.1.3`（host confusion / SSRF）、`sharp >=0.35.4`（libheif 漏洞）、`next >=15.5.24`（Windows RCE / Image Optimization API）、`browserslist ^4.28.7`（无界内存增长）。

### CI / DevOps

- **固定 Next.js 版本范围**（`c43571c`）：`>=15.5.24` 的 override 拉入 Next.js 16.3.5，默认启用 Turbopack 并破坏现有 webpack 配置。固定到 15.x 线以保持 webpack 为打包器
- **降低共享覆盖率阈值**（`20370d0`）：纯类型文件（`api-types`、`ws-types`、`security-log-ui`、`ui-fonts`）因导出类型/常量无运行时行为拉低语句/行覆盖率。阈值调整：语句 80→65、行 80→65、分支 75→70
- **修复 toHaveBeenCalled 测试断言**（`e416136`）：`useWebSocket.ts` 的 `toast.error` 调用新增 `id: 'session-terminated'` 选项，测试断言同步更新

### 测试基础设施

- `06bc279`、`dbf70b2`：PIN HMAC 基准测试——修正响应路径为 `data.data.sessionId`（`ApiResponse` 包装），使用 `postWithCookies` 助手从 cookie 取令牌

## 升级提醒

### 版本号跃迁说明

桌面端版本从 `1.3.11` 跃升至 `2.0.0`，原因：
1. **V2 Transfer Engine** 是面向传输链路的完整架构升级（新增上传方向、协议级取消、背压传播、完整性校验）
2. **不透明资源句柄** 改变 Web 客户端下载/预览的 URL 形态
3. **新 WS 协议消息类型**（`CMD_CANCEL_TRANSFER`、`RESP_TRANSFER_STATE`、`UPLOAD_START/END/CANCEL`）
4. **PathGuard V2** 路径匹配语义变更（最长匹配替代首匹配）
5. **Web 端 Store 公开接口重构**

### 兼容性

- **数据库**：无 schema 变更，无迁移
- **旧版 Web 客户端**：`/proxy/resource/:resourceId` 为新增路由，旧版 `filePath` 查询参数仍受支持
- **旧版桌面 Host**：可继续连接，但无法使用 V2 上传与协议级取消功能
- **协议**：V1 下载/预览帧格式保持兼容，V2 新增消息类型由 `validateMessage()` 版本感知
